# text-sanctifier Publish Checklist

The steps that are the same every time are scripted (scripts/release.js).

While working
- [ ] Put CHANGELOG entries under "## Unreleased" as changes land (what changed for someone using the package; see CLAUDE.md).
- [ ] `npm run ci` passes. Sizes, the release line and the pre-commit `rev:` in README.md and DESIGN.md are generated: if ci says they are stale, run `npm run gen`.

Release (patch bump only; work done close together goes out as one release)
- [ ] `npm run release:prep -- --dry-run`: checks main is clean and pushed, npm has the current version, and "## Unreleased" has entries; prints the next version.
- [ ] `npm run release:prep`: bumps the patch number, dates the CHANGELOG heading, runs `npm run gen` and `npm run ci`, commits "chore(release): X.Y.Z" and pushes.
- [ ] Maintainer: `npm publish --access public` (needs npm two-factor credentials), from the same checkout.
- [ ] `npm run release:verify`: waits for npm, checks the published gitHead, shasum and file count against the release commit, then tags vX.Y.Z on that commit and pushes the tag.

Changing the minor or major number is a deliberate decision, not a semver default; the scripts only bump the patch number.
